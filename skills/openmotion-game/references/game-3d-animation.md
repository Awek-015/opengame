# 3D Assets, Animation & Payload Discipline (Three.js + GLB)

Use for 3D characters, vehicles, props, environments, and animations in Three.js. Pair with [game-stylization.md](game-stylization.md) for cohesive lighting, textures, and skyboxes.

## 1. Capability-Driven 3D Asset Selection

Always check live capability discovery (`openmotion_capability_discover` / `openmotion_media_use`) first — noting each model's live rigging, quality tier, multi-view support, latency, and cost — then route by **screen dominance** rather than sending every object to 3D generation:

- **Hero, boss, signature weapons & primary-sightline architectural landmarks → 3D models (Image-to-3D preferred):** Concentrate high-fidelity 3D models on near-camera focal subjects (player character, boss, hero vehicle) **plus 1–3 reusable primary-sightline architectural landmarks** (e.g., carved temple archway/gate, beast-head bronze braziers, pagoda/dragon pillars) instanced around the arena. **Weapon PBR Parity Rule:** Never attach a giant flat solid-color `ExtrudeGeometry` paddle/axe or bare primitive slab to photoreal PBR `tripo-3.0` characters — it creates an instant plastic fidelity cliff. Either generate the Boss's ornate signature weapon via `3d-asset` (`tripo-3.0`, `prop-low`/`hero-balanced` from an isolated weapon concept) OR build weapons from multi-part dark forged bronze/iron PBR meshes with procedural canvas normal/roughness/engraving maps, beveled metallic collars, glowing rune cores, and realistic scale (`≤ 1.3×` wielder height). Prefer generating clean isolated studio concept sheets first (`text-to-image`) and passing them to Image-to-3D (`image_to_model`) over blind Text-to-3D so style, silhouette, and proportions stay locked.
- **Arenas, water mirrors, colliders & VFX → procedural geometry + GPU shaders + generated PBR textures:** Keep playable floors, mirror-water reflectors, collision boundaries, and dynamic effects in Three.js code with `fwidth()` anti-aliased floor inlays or seamless generated PBR textures so colliders match visuals 1:1 and close-up floors stay razor-sharp.
- **Visual Reference Sheet → Skeletal Pose / IK Contract (Action & Boss-Fight 3D):** Before authoring complex martial or boss choreography in code, generate one lightweight 4-panel Pose & Lighting Reference Sheet into `assets-raw/` (excluded from publish/ZIP) pinning down key poses (crouched combat guard idle, sprint, overhead heavy slam, hurt/dodge, warm-fire vs cool-moonlight contrast) so animation code and live captures can be audited against a concrete visual target.

**Generating & importing `.glb` models:** When `openmotion_capability_discover` (`action:"list"`, `modality:"3d"`) reports `3d-asset` available, invoke `openmotion_capability_run` (`capabilityId:"3d-asset"`, stable `requestId`, `options.quality`: `prop-low` / `hero-balanced` / `hero-high`, optional concept image in `references`). Because 3D generation can exceed short MCP client timeouts, **never resubmit with a new `requestId` on timeout** — re-invoke `openmotion_capability_run` with the **identical `requestId` and arguments** to resume from the saved remote task checkpoint without re-billing. Local `.glb` models can also be imported via `openmotion_asset_manage` / `openmotion_assets_use` (`action:"import"`, `sourcePath:"/abs/path/model.glb"`). Both generated and imported GLB 2 assets are automatically inspected into `version.result.glb` (with embedded PNG/JPEG textures WebP-optimized automatically via pure-Node `EXT_texture_webp` when saving/publishing) and served via `/motion-api/assets/<assetId>/versions/<versionId>/media`. Never encode binaries into `openmotion_game_write_files`. For high-importance focal actors, verify grounding, orientation, materials, and attachments in a clean view before layering heavy arena lighting or combat VFX.

## 2. Pre-Integration GLB Inspection Gate

Before wiring any external or generated `.glb` into a scene, inspect it with `node scripts/game-glb-inspect.mjs <file.glb>` (or read `version.result.glb` from an imported library asset):

- **Scale & grounding:** Check `bounds.size` (real world units) and `bounds.minY` (offset by `-box.min.y * scale` so feet/wheels sit flush on `y = 0`). Confirm forward facing (`+Z` vs `-Z`) and `rootTransforms` visually in a capture.
- **Materials & `alphaMode: BLEND` trap:** Check `materials.blendMaterials`. Third-party GLBs often misflag opaque meshes as `alphaMode: BLEND`, disabling depth-write so interior back faces draw over front faces (looks like inverted normals, except lit brightly instead of black). Force `material.transparent = false; material.depthWrite = true;` on parts meant to be opaque, while preserving genuine glass/windshield transparency and PBR roughness/metalness maps.
- **Animations:** Confirm `skins.length >= 1` and non-zero clip durations before referencing clip names; resolve via `THREE.AnimationClip.findByName` with explicit missing-clip handling. For one-shot hit/death clips, set `LoopOnce` + `clampWhenFinished = true`.

## 3. Payload Budget & CSP-Safe Compression

Inspect `totalBytes` and `textureRatio` in `game-glb-inspect.mjs` before optimizing — **on AI-generated 4K GLBs, 90–95% of file size is usually uncompressed PNG textures, not triangles**:

- **Preserve mesh geometry first, optimize textures:** `web_publish` and `exportZip` automatically transcode embedded PNG/JPEG textures inside `.glb` files to **`EXT_texture_webp`** at original resolution while preserving 100% of vertices, skins, and animations (`vendor/GLTFLoader.js` supports `EXT_texture_webp` natively with zero external decoders).
- **Avoid worker-based Draco decoders:** Game Studio's preview CSP enforces `worker-src 'none'`, which blocks Web Worker WASM decoders and external CDN loaders.
- **Keep raw masters out of delivery:** Archive raw 4K working masters or unused concept files under `assets-raw/` (excluded automatically from `web_publish` and `exportZip`), size procedural/terrain textures to their real on-screen resolution, and lazy-load secondary heavy forms (e.g., unlockable transformations/bosses) after initial boot.

## 4. Visual Craft, Smooth Motion & Performance Budget

- **Lighting, reflections & selective HDR bloom (style-matched):** Derive directional key light, ambient fill (keep `HemisphereLight <= 0.35` in dark/rainy mythic arenas so shadows stay moody instead of washed-out grey; keep bright fill for sunny/cozy styles), skybox/IBL (`PMREMGenerator`), rim highlights, and matching fog from `design/style.md`. Use `ACESFilmicToneMapping` + `SRGBColorSpace` on color/emissive maps only (linear on normal/roughness/metalness). For atmospheric, dark-mythic, sci-fi, or emissive-heavy 3D scenes, do not stop at flat un-bloomed `renderer.render()`: combine style-appropriate specular/planar-mirror floors (`768–1024px` `WebGLRenderTarget`, hiding particles/shadows in the mirror pass, clamping oblique/edge UVs, and **never** using `pow(<=0.0, k)` or reversed `smoothstep(hi, lo, x)` in GLSL) with a probed WebGL2 `4× MSAA` `HalfFloatType` selective Bloom composite (`bloomThreshold ~0.72`, `bloomStrength 0.25–0.38`, graceful fallback to single-sample/LDR if `EXT_color_buffer_float` or MSAA is unsupported) so emissives glow cleanly without blurring armor or vehicle edges.
- **GLSL `NaN` black-square firewall & juicy combat VFX:** On Apple Silicon Metal/ANGLE WebGL2, `pow(0.0, k)` or `pow(negative, k)` in trail/mirror shaders produces `NaN` pixels that a `HalfFloatType` Gaussian Bloom pass smears into giant **black squares**. Always clamp `pow(max(0.001, base), k)` in every custom shader, sanitize `HalfFloat` taps in bright-extract/blur/composite passes (`if (!(sum >= 0.0 && sum < 65000.0)) return vec3(0.0)`), and pair every melee strike with **(1) a dynamic multi-segment glowing weapon ribbon trail (`≥ 12` samples, additive NaN-safe shader)**, **(2) circular radial-glow GPU hit sparks (`if (dot(c, c) > 1.0) discard;`, `fog: false`, never default `PointsMaterial` squares)**, **(3) `55–75 ms` Hit-Stop + damped camera kick**, and **(4) glowing ground crack/shockwave decals on heavy slams**.
- **Zero-jitter martial skeletal animation, IK & camera smoothness:**
  - **Kill the upright A-pose puppet & detached floating weapons:** Never leave a melee hero or boss standing bolt-upright with wide horizontal A-pose arms in combat idle, and **never rotate/raise a weapon independently while the wielder's rigged arms hang straight down at their sides**. Parent primary weapons directly to the rigged dominant `Hand` bone socket (or derive weapon transform strictly from animated `RightHand` → `LeftHand` bone world positions *after* `pose.updateMatrixWorld(true)`). For every Boss telegraph (e.g. overhead slam, wide sweep, charge), **physically rotate spine + shoulders + elbows into the wind-up pose first** so the arms visibly lift and swing the weapon!
  - **Grounded martial guard stance:** Knees visibly bent (`thighX ~ -0.22`, `calfX ~ +0.34`), pelvis lowered (`-0.06` to `-0.10`), spine pitched forward & twisted (`spineX ~ +0.16`, `spineY ~ -0.22`), shoulders relaxed and elbows tucked inward (`35°–55°`) holding the staff/weapon diagonally across the body. Every attack must animate a clear **3-beat Anticipation (coil/wind-up) → Strike (torso whip + forward lunge + trail) → Follow-Through (weight settle)** curve.
  - **Never reset rigged bones to T-pose every frame (`for (const [b,q] of rest) b.quaternion.copy(q)` is forbidden during live pose blending):** Maintain persistent per-bone `curQ` quaternions initialized from rest pose and exponentially `slerp` toward each frame's target pose (`curQ.slerp(tgtQ, 1 - Math.exp(-rate * dt)); bone.quaternion.copy(curQ);`) so idle ↔ sprint ↔ combo ↔ hurt transitions stay liquid-smooth.
  - **Apply spine rotation before arm aiming, and add analytical 2-bone off-hand IK** with an outward elbow pole vector when wielding two-handed weapons (compute target upper-arm direction via law of cosines: `cosA = clamp((L1² + d² - L2²) / (2*L1*d), -1, 1)`, bend elbow toward pole vector, then `aimBone` upper→elbow and elbow→hand) so the off-hand grips the shaft cleanly without hanging at the hip or clipping chest armor.
  - **Third-person rear-silhouette hero readability:** Because the camera views the hero's back 95% of the time, hero concept art MUST lock unmistakable rear landmarks (bright metallic gold pauldrons, high-contrast crimson cape/sash, iconic headgear/crown visible from behind) and attach a dedicated warm rim/back fill light (`intensity >= 1.2`) tracking the hero so rear armor never turns into a dark muddy blob.
  - **Reuse sculpted meshes for clones & avatars:** Use `SkeletonUtils.clone()` with translucent glowing astral materials for spirit clones, dodge afterimages, and giant avatars instead of primitive capsules or wireframes.
  - **Signed-angle & frame-pacing safety:** Always compute shortest turning delta from `current` toward `target` as `Math.atan2(Math.sin(target - current), Math.cos(target - current))` (an inverted `current - target` sign causes violent 180° spin-jitter!). Smooth **both** camera position and `lookAt` target, call `camera.updateMatrixWorld()` before projecting HUD markers, hold lock-on heading when fighters cross at close range (`d < 1.8m`), and either interpolate fixed-timestep transforms or step with clamped `dt <= 1/30` so 120 Hz ProMotion displays never micro-stutter.
  - **Timebox polish to avoid session stalls:** Inspect GLB bone names directly from `version.result.glb` / `game-glb-inspect.mjs` (never run ad-hoc binary-parsing surgery loops late in a turn). Keep total build + 1 focused 5-pillar polish pass tight (~15–20 minutes).
- **Asset rejection safety valve:** Visual cohesion and close-up clarity outrank asset provenance. If an external or generated 3D model reads blurry, fused, or stylistically jarring in live captures, discard it and replace or fall back to clean procedural geometry + lighting rather than defending sunk cost.
- **Draw calls & lifecycle:** Merge static compatible geometry once (`BufferGeometryUtils.mergeGeometries`), use `InstancedMesh` for swarms/props (never merge skinned meshes), cap DPR ≤ 1.5, keep typical scenes within ~120 draw calls / ~150k rendered triangles where practical, expose real scene draw/triangle counts (captured *before* any final fullscreen post-process quad resets `renderer.info`) in `window.__omGame.getStats()`, and dispose detached resources cleanly.
- **Multi-frame motion & headless QC gate:** Static screenshots alone miss yaw oscillation, camera stutter, and hit-frame drift. Always run a multi-frame playtest sequence sampling consecutive frames during real movement, turning, dodging, and combat — verify `0` console/WebGL errors, bounded per-frame yaw delta (`|Δyaw| < 0.35 rad`), bounded camera step, and passing `window.__omGame.runSelfTests()`. Server playtests run SwiftShader WebGL — FPS there is pacing only, not real GPU performance, but blank canvases, console errors, failed GLB/texture requests, yaw oscillation, and runaway `renderer.info` counts are real failures to fix.
